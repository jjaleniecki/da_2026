Preguntas:
1. Mostrar paso a paso cómo se divide el arreglo [38, 27, 43, 3, 9, 82, 10].
                 [38, 27, 43, 3, 9, 82, 10] 
        [38, 27, 43, 3]     |       [9, 82, 10]
[38, 27]   |   [43, 3]      |   [9, 82]   |   [10]
[38] [27]  |   [43] [3]     |   [9] [82]


2. Derivar la recurrencia T(n) y resolverla con el método maestro.
    Se resuelven 2 subproblemas de tamaño n/2.
    El paso merge recorre los n elementos una vez, así que cuesta Θ(n).
    El caso base es Θ(1).

T(n) = 2·T(n/2) + Θ(n), con T(1) = Θ(1)

Con la forma T(n) = a·T(n/b) + f(n), tenemos a = 2, b = 2 y f(n) = Θ(n).

    Se calcula n^(log_b a) = n^(log₂ 2) = n¹ = n.
    f(n) = Θ(n) = Θ(n^(log_b a)), así que se aplica el caso 2 del teorema maestro.

T(n) = Θ(n log n)

La intuición es que hay log₂ n niveles de división y en cada nivel se hace un trabajo total 
de n en las mezclas. Para n impar los tamaños son ⌈n/2⌉ y ⌊n/2⌋, y el resultado es el mismo.

3. ¿Por qué este enfoque mejora a la fuerza bruta?
Mergesort gana por tres razones:

Subproblemas independientes y chicos: ordenar dos mitades de n/2 es mucho más barato que ordenar 
n de una vez, porque el costo crece más que linealmente.
Mezclar listas ya ordenadas es lineal: como cada mitad está ordenada, alcanza con comparar las 
cabezas de ambas listas. No hace falta comparar cada elemento contra todos los demás.
Aprovecha el trabajo ya hecho: el orden logrado en los niveles de abajo se reutiliza en los de arriba. 
Cada elemento participa en solo O(log n) mezclas.

El costo es memoria extra O(n) para el arreglo auxiliar, algo que la fuerza bruta (selección, burbuja) 
no necesita.
